# ADR 0003 — Atlas IR as the central abstraction

**Date:** 2026-07-03  **Status:** Accepted

## Decision

All data flowing through Atlas is first mapped to IR types defined in `crates/ir`.
No crate except `crates/ir` defines its own domain structs.

## Why

- The graph primitives (Entity, Relationship, Evidence) can later be queried uniformly
  regardless of whether the data came from git, GitHub, or another source.
- Keeping IR pure (no I/O, no logic) means it can be serialized, stored, tested,
  and reasoned about in isolation.
- When a new source is added (Jira, Linear, Slack), it maps to the same IR — the
  storage and query layers don't change.

## Alternatives rejected

- **Source-specific structs throughout**: Fast to start. Impossible to join across
  sources without large refactors.
- **Generic `HashMap<String, Value>`**: Flexible but loses type safety everywhere
  it matters.
